# SPEC v0.8：迷你棋盘关卡 + 金币经济

> 状态：已定稿（访谈三轮收敛，2026-09-30）
> 术语见根目录 `GLOSSARY.md`；结构决策见 `docs/adr/0001`、`docs/adr/0002`。
> 市场调研参考归档于 `design/research/`（两份，随调研完成补充引用）。

> **修订 2026-09-30（试玩反馈轮）**：
> 1. **实施端收缩为仅 HTML 模拟器**（`ios/preview/index.html`），Swift 原生端暂缓不再追平——见 `docs/adr/0003`。本文所有涉及 Swift 实现的决策，验收口径一律以模拟器端为准。
> 2. 试玩反馈落地：地图「命运骰子」跳关入口撤除（进度只靠玩关卡）；棋盘途经题目格必须逐格作答、掷大点数=多做几题；商店下架骰子皮肤、改售**称号**（金币只换角色与称号，展示于地图铭牌）；科学岛实验完成后可自由重玩、不再死锁；五学科普通关全部棋盘化，每关题库扩产至 ≥5 道变体（count 题加 countRange 由客户端每次随机取数）。
> 3. 金币数值口径按儿童教育调研微调：金币更直接映射掌握度（答对 +2、金币格 +5、宝箱 3-8、3 星 +5、boss +15 维持不变），问号砖每根水管每天限一次。

## Problem Statement（问题）

v0.7 的马里奥元素是"摆件式堆积"：小人只会在地图节点上蹦跳，骰子按钮只是随机跳转入口，金币只进不出、毫无用处——孩子没有持续的游戏动机。更糟的是，Swift 原生端的通关结算画面因缺陷根本无法触达，最该有仪式感的一刻是坏的。家长（产品负责人）希望把《超级马里奥派对》的结构语言真正融进学习流程，而不是继续贴皮。

## Solution（方案）

v0.8 把"做题目"变成"在棋盘上冒险"：

- **每关 = 一条 8-10 格的迷你棋盘**：孩子亲手掷骰前进，格子决定遭遇——题目格答题、金币格/宝箱格/幸运蘑菇格/休息站格结算，走到终点城堡通关。
- **金币双轨制**：星星管学习进度（解锁关卡只看星星），金币只买个性表达（角色、骰子皮肤的商店），永远买不到学习内容。
- **关卡原型扩充**：每学科新增 2 个复习关（旧题混排棋盘）+ 1 个 boss 关（3 颗心血条挑战，学科通关后解锁）。
- **马里奥式结算仪式**：旗杆滑下 → 城堡门开 → 金币雨逐枚计数 → 星星逐颗点亮；约 4 秒可跳过。修复原生端结算不可达的缺陷。
- 流程沿用：HTML 设计稿先行定稿 → Swift 原生端追平，两端共用同一份关卡 JSON。

## User Stories（用户故事）

1. 作为孩子，我想进入关卡时看到一条蜿蜒的棋盘路径和站在起点的角色，这样我感觉是要去冒险而不是要做题。
2. 作为孩子，我想亲手掷一个大骰子看着它滚动落定，这样每回合开始都有仪式感。
3. 作为孩子，我想骰子落定后角色沿路径蹦跳前进对应的格数，这样我能数着格子期待落点。
4. 作为孩子，当我落在题目格时我想马上玩一题当前学科的内容，这样冒险和学习是同一件事。
5. 作为孩子，我答对题目后想看到金币叮当入账，这样我知道自己做得好。
6. 作为孩子，我答错题目后不想被惩罚或后退，我想再试一次或继续前进，这样我不会沮丧。
7. 作为孩子，我落到金币格时想看到旋转金币炸开的爽快动画，这样纯粹的运气也有惊喜。
8. 作为孩子，我落到宝箱格时想翻开宝箱拿到 3-8 枚不等的金币，这样每次落点都有悬念。
9. 作为孩子，我吃到幸运蘑菇后想知道它有实际作用——下一次答错不算错，这样蘑菇是道具而不是装饰。
10. 作为孩子，我路过休息站格时想看角色进小房子喝口水的动画，这样棋盘上有生活的趣味。
11. 作为孩子，我走到终点时想滑下旗杆、看城堡门打开，这样通关像马里奥一样有终点的仪式。
12. 作为孩子，我想看到本次赚的金币像雨一样逐枚掉落并计数，这样奖励看得见摸得着。
13. 作为孩子，我想看星星一颗颗砸下来点亮（错 0 题 3 星、错 1 题 2 星、错 2 题及以上 1 星），这样我知道自己这关的表现档位。
14. 作为孩子（或陪玩的家长），我想点按屏幕就能跳过结算动画，这样反复通关时不烦。
15. 作为孩子，我玩复习关时想遇到以前学过的字/拼音/单词混在一起出现，这样复习不枯燥还像开盲盒。
16. 作为孩子，我通关一个学科后想解锁一个 boss 大挑战关，这样全通后有更厉害的目标。
17. 作为孩子，打 boss 时我想看到它有 3 颗心、我答对就打它一下、它答错撞我掉一颗心，这样紧张感是游戏给的而不是分数给的。
18. 作为孩子，我的心被 boss 撞光后想直接重试，这样失败不产生损失。
19. 作为孩子，击败 boss 后我想拿到一大笔金币（15 枚），这样大挑战有大回报。
20. 作为孩子，我想在地图上看到一间小商店建筑并走进去，这样"赚了钱要花"有真实的去处。
21. 作为孩子，我想在商店里浏览角色和骰子皮肤的货架并看清每件价格，这样我有攒钱的明确目标。
22. 作为孩子，金币够时我想一键买下心仪的角色，这样努力马上变成拥有。
23. 作为孩子，金币不够时我想得到友好的提示（差多少），这样我知道还差几次通关。
24. 作为孩子，我想在衣橱里随时切换已拥有的角色，这样地图和结算里的小人跟着换。
25. 作为孩子，我想换一枚骰子皮肤（水果点、动物脚印点等），这样我最常用的道具有我的印记。
26. 作为家长，我想让孩子已有的星星、金币和通关进度在升级后原样保留，这样孩子不会因为版本升级哭鼻子。
27. 作为家长，我想让新插入的复习关不挡住已有进度，这样升级当天体验无缝。
28. 作为家长，我想地图问号砖的免费金币每根水管每天只给一次，这样孩子不会靠刷砖头绕过做题攒钱。
29. 作为家长，我想护眼休息只在关卡结算后触发而不是棋盘中途打断，这样保护视力的规则不破坏一局游戏的完整体验。
30. 作为家长，我想每日游玩总量限制保持不变，这样棋盘变长不会变相延长屏幕时间。
31. 作为家长，我想在家长中心看到金币的获得与消费统计，这样我了解孩子的奖励循环是否健康。
32. 作为孩子，我想全程静音也能完整游玩（所有反馈有视觉等价物），这样飞机上也好玩。

## Implementation Decisions（实现决策）

**内容层（关卡 JSON 与生成器）**
1. 关卡模型获得棋盘语义：每关新增格子序列，格子类型为 question / coin / chest / mushroom / rest，question 格引用现有 step 题型数据（14 种 kind 不变）。
2. 普通关 8-10 格：题目格 5-6 + 金币格 1-2 + 事件格（宝箱/蘑菇/休息站）1-2，**题目格占比 ≥ 60%** 为内容校验红线；复习关 10-12 格（旧题混排 + 事件格加倍）；boss 关为血条制连续题目格（约 8 题，3 颗心）。
3. 关卡原型按学科扩充：每学科在原 10-15 关基础上插入 2 个复习关（约第 5、10 关之后）+ 1 个 boss 关（学科全部通关后解锁）；复习关默认解锁不挡路。
4. 路径形状（蛇形/弧线蜿蜒）由渲染层按格子数计算布局，不进 JSON；JSON 只存格子序列与题目引用。
5. 内容生成器（Python 表驱动）扩展生成棋盘数据，浏览器模拟器与原生端继续共用同一份 JSON 注入。

**玩法层（骰子与格子结算）**
6. 骰子真实驱动前进：掷骰 → 角色沿路径逐格蹦跳 → 落格结算。骰子滚动动画复用现有 0.8s 滚动落定实现。
7. 落题目格必须作答：答对 +2 金币并结束该回合；答错不后退、不扣任何东西，可重答（防挫败铁律）。
8. 幸运蘑菇是消耗性 buff：吃到后持有，下一次答错不计数并重答一次，用完即消失；boss 关内同样生效。
9. boss 关：boss 3 颗心、玩家 3 颗心；答对打 boss 一下（掉一心），答错被撞一下（掉一心），boss 心先空则胜利，玩家心空则友好失败并可直接重试（无损失）。
10. boss 为原创同风格大角色（如大乌龟），美术走现有 SVG 生成管线（美术唯一源）。

**经济层（金币、商店、衣橱）**
11. 金币口径：答对题目格 +2、金币格 +5、宝箱格 +3~8 随机、3 星通关额外 +5、击败 boss +15。现有存量金币保留。
12. ProgressStore 增加金币账本（交易记录：来源、数额、时间），HUD 显示总额；金币从此只经账本变动，删除"无限点砖 +1"的旁路。
13. 地图问号砖改为每根水管每天限领一次（按水管标识 + 日期记录）。
14. 商店两品类：角色 6 款（现有 2 款 + 新增 4 款原创同风格小伙伴）、骰子皮肤 4-6 款（点面换成水果/动物脚印/星星等）；定价 40-120 金币（单件 ≈ 3-6 次通关）。
15. 购买与激活分离：拥有集合 + 当前激活（角色一枚、骰子一枚），激活即时生效于地图、棋盘、结算。
16. 收集册新增"衣橱"分区管理已购与激活状态；商店入口为地图上的商店建筑。
17. **双轨制铁律（ADR-0002）**：关卡解锁只看星星；金币永远买不到学习内容。任何"金币解锁关卡/跳关"的设计都被此铁律挡住。

**进度与迁移**
18. 关卡 id 平移迁移：现有关卡 id 一律不变，新关插入后仅位置后移；已有星星、金币、收集册按 id 对齐，不重置任何进度。
19. 清理死设置"解锁全部"（只写不读）；难度设置保留现状不动。

**结算仪式与缺陷修复**
20. 结算序列：角色滑旗杆（按星级决定滑到底/中途）→ 城堡门打开 → 金币雨按本次所得逐枚掉落计数 → 星星逐颗砸下点亮 → 按钮组浮现；总时长约 4 秒，点按任意处跳过。
21. 音效用现有合成器升级为原创上行音阶旋律（避开任天堂版权）；静音模式下全部反馈有视觉等价物。
22. **修复原生端结算不可达缺陷**（最后一步答完后 `finished` 永不置真，结算卡只在浏览器模拟器可达）。

**护眼与家长**
23. 棋盘进行中不触发休息遮罩：达到单次时限时等待本关结算完成再进入休息；每日总量限制与既有三档设置不变。
24. 家长中心进度面板增加金币获得/消费的只读统计。

**流程与双端**
25. HTML 设计稿先行：design 目录新增棋盘关、商店/衣橱设计稿，视觉在模拟器上快速迭代定稿后再实现 Swift 原生端（既有双轨流程）。
26. 视觉主题沿用现有 design token 体系（CSS 变量与 Swift 主题一一对应），棋盘新元素（格子、商店建筑、boss）纳入同一 token 体系，圆角字面值顺手收敛为 token。

## Testing Decisions（测试决策）

- **测试缝：领域层，不新开缝。** 挂现有三件套——内容完整性测试（ContentIntegrityTests）、存储测试（StoreTests）、逻辑测试（LogicTests）+ 静态校验脚本（validate.py）。理想缝数 = 1：内容 JSON + ProgressStore 状态机。
- 只测外部行为，不测实现细节：给定关卡 JSON 与进度快照，断言可观察结果（棋盘结构合法性、金币账本余额、能否购买、解锁状态、迁移后进度），不断言内部视图结构或动画参数。
- 内容完整性新增断言：每关格数区间、题目格占比 ≥ 60%、关卡 id 全局唯一（迁移前提）、boss/复习关标记与格子构成匹配、商店物品定价区间与 id 唯一。
- Store 测试新增断言：金币账本只经记账变动且永不透支、购买/激活/重复购买、buff 持有与消耗、问号砖按日限次、旧进度按 id 迁移不丢星。
- 逻辑测试新增断言：boss 心结算（答对/答错/双方心空优先级）、星级映射不变（0/1/≥2 错 → 3/2/1 星）。
- UI 动画、掷骰手感、结算演出**不做自动化测试**，验收走 HTML 设计稿走查 + 真机/iPad 手工走查（仓库既有惯例）。

## Out of Scope（不做）

- 多人/亲子对战（明确决定：就孩子自己玩；如未来重启见 ADR-0001 后果注记）。
- 题目交互升级（拖拽、拼音描红、连线匹配等新操作方式）→ v0.9。
- 全局视觉质感打磨、背景音乐制作 → v0.9（v0.8 仅结算音效升级）。
- 商店岛屿装饰品类 → v0.9+。
- 金币相关的家长管控设置（如关闭商店）→ 观察使用后再议。
- 收集册既有 7 组内容的扩容（仅新增衣橱分区）。
