## Standards（标准轴）

### 硬违规（有文档依据）

1. **商店完全没有校验闸门。** `docs/specs/0001…md` Testing Decisions 要求「商店物品定价区间与 id 唯一」；`ios/tools/validate.py` 对 `shop` 零引用，`ios/Tests/` 亦零（`grep shop|price`）。`shop.json` 有生成、无闸门。
2. ✓ **两套内容闸门互相矛盾。** `ios/Tests/…/ContentIntegrityTests.swift:20-22` 断言 17/17/14/14/12 关，`validate.py:37` 与实际产物为 18/18/15/15/13。按 `ios/README.md` 所述闸门跑 `Cmd+U`，对着已发布内容必然失败。
3. ✓ **科学岛「收进图鉴」按钮点不亮。** `ios/preview/index.html:1976` 判据是 `if(b&&!b.disabled)`，而 `#collectBtn` 两个分支（`:1877`、`:1878`）都渲染成 `disabled`，条件永假。规格里的 实验演示→贴纸 闭环断裂；由 `4d0bb22` 引入。
4. **每日护眼上限不持久。** 规格决策 23 / story 30。`save()`（`:518`）漏存 `playSec/daySec/dayKey/resting`，刷新即重置计时；而 `S.brick` **是**持久的——同一份 state 两种处理，自相矛盾。
5. **设计 token 规则（决策 26）。** 新棋盘/商店/boss 样式直接写十六进制：`index.html:182-186`（`#FFE9AE,#F5B93B`、`#9B7BF5`、`#58C96B`）、`:456`；Swift 侧另有 8 处字面 `cornerRadius:`（`BoardView.swift:149,152,552`；`BossView.swift:214-266`）。
6. **`ios/README.md` 全面过期**：`:4` 关卡数、`:26`「18 项」vs `:79`「12 项全过」、「6 个测试类 20 个用例」（实际 4 类 59 例）、「12 种步骤」（已发 14 种）、目录树缺 `shop.json`、无 ADR-0003 指引。

### 干净项

图标约定（94 个 imageset = 94 个 `IconEmoji` 键，validate 已确认）；**ADR-0002 铁律**（`nodeState` `:647` 只以 `S.stars` 作解锁判据、商店只卖角色/称号、骰子跳关入口已撤 `:728`）；`GLOSSARY.md` 禁用词（无禁用词被用作标识符/JSON 键/用户可见文案，仅 `:1160` 注释里出现「结算卡」）。

- **重复代码**：`shopCard`(`:735`) 与 `wardCard`(`:776`) —— owned/active + 按钮态那套流程几乎逐行相同。
- **重复 switch / 基础类型偏执**：`kind==="chars"?S.ownedChars:S.ownedTitles` 在 `:548,550,560,562,736,737,777,778` 出现 8 次。

## Spec（规格轴）

> 验收载体按 ADR-0003 以模拟器为准。分三类：(c) 实现了但实现错了 / (a) 缺失或半成品 / (b) 没要求却做了。「挂起」单列，不算失败。

### (c) 实现了但实现错了

1. ✓ **落格结算丢失（影响最大）。** `index.html`：`arriveBoard()` 在途经 ≥1 个题目格时于 `:1159` 提前 return，走不到 `:1161` 的 `resolveSpace(p)`；`boardStepDone()` 答完队列后直接 `mode="roll"`（`:1234`）。于是**你踩中的那一格（金币/宝箱/蘑菇/休息站）什么都不发**。而所有生成的棋盘都把事件格放在 index 2（例：`cn-0` 为 q,q,**coin**,q,q,**coin**,q,**chest**,q），即首掷掷出 3 就静默吞掉 金币格 +5。违反 `.scratch/v0.8-board/spec.md` 决策 6「掷骰 → … → 落格结算」与 工单03「金币格落上即 +5」。
2. ✓ **进度迁移漏了键名（违反决策 18 / US26「已有星星…按 id 对齐，不重置任何进度」）。** `settleLevel`/`nodeState` 改以关卡 id 为键，旧存档用 `subject-index`，`load()` 无迁移：`pinyin-N`→`py-N`、`english-N`→`en-N` ⇒ **拼音谷与英语王国已存星星在孩子设备上被清零**（cn/math/astro 只是键形恰好撞上）。`StoreTests` 只测 `cn`，所以一路绿灯。
3. ✓ **发到孩子手里的包是旧的。** 根目录 `探险岛-HTML离线包.zip` 最后生成于 `b616a65`（09-30），试玩反馈修复在 `4d0bb22`（10-01）。zip 内仍是撤回后的命运骰子 `rollDice`、`shop.dice` 骰子皮肤、非 cn 关无 `board`、无 `countRange`、无称号——**修订轮的全部改动都没到达孩子**；配套 `探险岛-iPad使用说明.txt` 还在宣传骰子皮肤与「与原生版完全一致」。
4. **3 星 +5 实际只是求和。** 现为 `earn("level-stars",stars)` + `earn("mushroom-bonus",2)`；`StoreTests` 断言 3 星通关得 3 金币，家长面板标注「完美蘑菇奖励 +2」。boss 奖励双端不一致（模拟器 15，Swift 15+星星，后者属挂起项）。
5. **工单10 漏口：** `checkRestAfterSettle()` 只被 `settleLevel()` 调用，boss 从不置 `lv.finished`，于是决策 23 的休息断点在 boss 战后永不触发。

### (a) 缺失 / 半成品（真未满足，非挂起）

- 新划的红线没有闸门：`validate.py`（98 项通过）对 `shop.json` 零检查，尽管 Testing Decisions 写明「商店物品定价区间与 id 唯一」；也没有任何东西断言「每关题库扩产至 ≥5 道变体」——目前达标只是碰巧。
- 决策 2「金币格 1-2」：`math-5/9/14`、`py-11`、`en-11` 金币格为 0。boss 解锁条件是「正式关全通」，把复习关排除在外，与 工单06「学科全部通关后才解锁」不符。
- 决策 25 / 工单02「设计稿定稿入库」超额声明：没有新增 `design/*.html`，只加了 SVG。
- 初始 state 不自洽：`activeTitle:"xiaoxian"` 但 `ownedTitles:[]` ⇒ 地图铭牌显示一个未拥有的称号，切换后无法再装备。

### (b) 没要求却做了

- 提交进仓库的 213 KB zip + 使用说明（无工单覆盖）。
- 已下架功能的残留：`paw.svg`、`.shop-dice` CSS、未被调用的 `diceFaceHTML`、`activeDicePip()` 桩。
- `GLOSSARY.md` 未随之修订（仍写金币可换骰子皮肤），且 `.scratch/v0.8-board/spec.md` 与已入库的修订版内容不一致。

### 按 ADR-0003 挂起（列出，不计为失败）

Swift 缺 途经必答 队列（`BoardView.arrive`）、商店/衣橱/称号、结算音效升级；`MapView` 仍保留命运骰子；`ContentIntegrityTests` 期望 17/17/14/14/12 vs 实际 18/18/15/15/13 ⇒ XCTest 现为红。解除冻结时应「以最新 `docs/specs/` + 模拟器实际行为为准重建」，而非在旧 Swift 上增量改。

### 干净项

工单 01（星星规则回归测试确有真实断言）、03、04、05、07、08（遵守 ADR-0002，仅换装扮）、09、10（除 boss 路径外）。

## 第一轮留痕（已被 ADR-0003 部分推翻）

基准点同为 `0c1a4f8`，但当时 HEAD 为 `b616a65`（8 提交 / 69 文件 / +8,809），`docs/adr/0003` 与 `docs/specs/0001` 的修订块尚未存在。重跑结果差异全部来自那两条文档变更：

- **作废**：第一轮的头号硬违规「双端失同步——工单08/09 商店、衣橱、金币消费只落在模拟器，原生没有」，以及「`shop.json` 在原生是死资源」。ADR-0003 把 Swift 定为冻结、验收面收缩到模拟器，这属于仓库明文决策，按「仓库文档优先于气味基线」直接压制。
- **降级**：「HTML 端途经题目格排队作答 = 未声明机制」「五学科未全部棋盘化（仅识字村）」——前者被修订块明文要求（途经必答、五学科全棋盘化），后者已在 `4d0bb22` 完成。「3 星 +2 与 spec +5 冲突」维持，因修订块反而重申了 +5。
- **保留且现已更严重**：星星键名迁移漏项（原生侧同样存在，但孩子用的是模拟器）；内容闸门数字不一致。
